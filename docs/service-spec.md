## 1. 언어와 도구

### 1-1. 언어
| 영역 | 언어 | 비고 |
|---|---|---|
| 앱(화면·로직) | **TypeScript** | 현재 프로젝트와 동일. `.ts` / `.tsx` |
| 서버 함수 | **TypeScript** (Supabase Edge Functions, Deno) | 앱과 타입 공유 |
| DB | **SQL** (PostgreSQL) | 마이그레이션 파일로 관리 |
| 빌드 스크립트 | JavaScript(Node.js) | 기존 `scripts/build.js` 정리 후 유지 또는 제거 |

### 1-2. 프레임워크·라이브러리
| 구분 | 도구 | 용도 | 상태 |
|---|---|---|---|
| 앱 프레임워크 | React Native + **Expo SDK 54** | 화면 구현, 웹 빌드 | 기존 유지 [확정] |
| 라우팅 | **Expo Router** | 파일 기반 화면 이동 | 기존 유지 |
| 웹 렌더링 | React Native Web | 웹앱(PWA) 실행 | 기존 유지 |
| 서버 상태 | TanStack Query | API 캐시·재시도 | 기존 포함, 실사용 |
| 클라이언트 상태 | React Context + reducer (기존 `AppContext`) | 운동 세션 진행 상태 | 기존 유지, 축소 |
| 로컬 저장 | AsyncStorage (웹은 localStorage) | 비로그인 임시 저장, 마지막 자세 등 | 기존 유지 |
| 영상 재생 | HTML5 `<video>` (웹) / `expo-video` (네이티브 대비) | 연속 재생·재생 시간 측정 | 신규 [제안] |
| 화면 꺼짐 방지 | Screen Wake Lock API / `expo-keep-awake` | 영상 중 화면 유지 | 신규 [제안] |
| 날짜 | `date-fns` + `date-fns-tz` | KST 기준 날짜 계산 | 신규 [제안] |
| 검증 | `zod` | 서버 응답·입력값 검증 | 기존 포함 |
| PWA | Service Worker, Web App Manifest, Web Push(VAPID) | 홈 화면 추가, 알림 | 신규 [제안] |
| 제거 | `expo-image-picker`, `expo-location`, `@workspace/api-client-react`, Replit 설정 | 사용 안 함 | 제거 |

### 1-3. 서버·운영 도구 [제안 — 기획서에 없음, 확정 필요]
| 구분 | 도구 | 이유 |
|---|---|---|
| 백엔드 | **Supabase** (PostgreSQL, Auth, Edge Functions, Storage, Cron) | 익명→소셜 계정 연결, 카카오·구글 로그인, 서버 코드 최소화 |
| 로그인 | Supabase Auth (Google) + **Kakao OIDC** | 기획서: 카카오·구글 |
| 영상 저장·전송 | Supabase Storage 또는 Cloudflare R2 + CDN | 1분 MP4 약 20개 |
| 콘텐츠 관리 | **Google Sheets** → Edge Function 동기화 | 기획서: 스프레드시트 관리 |
| 알림 발송 | Edge Function + pg_cron + `web-push` | 매시 정각 발송 |
| 지표 | DB View + Looker Studio(또는 Supabase 대시보드) | 관리자 지표 열람 |
| 배포(웹) | Vercel 또는 Cloudflare Pages (정적 호스팅) | 별도 서버 불필요 |
| 오류 추적 | Sentry | 베타 "핵심 기능 정상 작동률" 측정에 활용 가능 |
| 형상관리 | Git (현재 clone 저장소), 브랜치 단위 작업 | |
| 품질 | ESLint, `tsc --noEmit`, Playwright(핵심 플로우 E2E) | 정상 작동률 95% 검증 보조 |

> 위 서버 도구 선택은 비용·구현 방식이 걸린 사안이라 기획서 협의 항목("로그인·서버 저장 방식과 월 비용")에 해당합니다. 개발자 견적 결과에 따라 바뀔 수 있습니다.

## 4. 화면별 상세 명세

### C-02 재시작 환영
**목적**: 쉬었다 돌아온 사용자를 홈보다 먼저 환영한다.

**진입(자동)**: 앱 실행 시 아래를 모두 만족하면 홈 대신 표시. 하루에 1번만.
1. 운동 이력(움직인 날)이 1일 이상 있음
2. 어제(KST)에 움직인 날이 아님
3. 오늘 이미 움직이지 않았음
4. 오늘 이 화면을 본 적 없음

**구성**
| 요소 | 내용 |
|---|---|
| 작물 이미지 | 쉬기 전 상태 그대로의 방울토마토 성장 단계 |
| 환영 문구 | 문구 시트에서 1개 선택(아래 규칙) |
| 버튼 [바로 1분 하기] | 자세를 거치지 않고 **M-01로 이동** (기획서: "바로 1분 하기") |
| 버튼 [홈으로 가기] | H-01로 이동 |

| 버튼 [이어서 하기] | **중간에 멈춘 영상(세션)이 있을 때만** 표시. 멈춘 지점부터 M-03 재개 [확정 ⑯] |

**문구 선택 규칙 [확정]**
- 휴식 기간: 1~2일 / 3일 이상
- 이용 관계: 앱 이용 1개월 초과 **그리고** 운동일 20일 이상이면 "오래 이용", 아니면 "그 외"
- 4개 그룹에서 해당 그룹의 문구를 고르되, 최근 2개와 같은 문구는 제외
- 문구는 스프레드시트 `welcome_messages`에서 가져옴

**금지**: 쉰 날 수, 재시작 횟수, 연속 기록 문구 표시

**예외 처리**
- 문구 시트가 비어 있거나 불러오기 실패 → 기본 문구 1개("다시 와주셔서 반가워요")를 앱에 내장
- 로그인 안 한 사용자도 동일하게 표시(기기에 저장된 기록 기준)

| # | 요소 | 동작 |
|---|---|---|
| 1 | 오늘의 한마디 | 시간대별 문구 1개 표시. 탭 동작 없음 |

| 3 | 농장 요약 카드 | 현재 작물 단계 이미지, 물방울 보유 수, 오늘 획득 n/5. 탭 → F-01 |
| 4 | 이번 달 요약 | 운동한 날 수, 총 운동 분(인정 시간 합) |
| 5 | 월간 캘린더 | 움직인 날에만 표시. 쉰 날은 아무 표시 없음. 이전/다음 달 이동 [‹] [›] |
| 6 | 최근 운동 3건 | 날짜·자세·인정 시간. 탭 → H-02 해당 기록 |
| 7 | 주간 운동시간 그래프 | 이번 주 일별 인정 분. 기존 그래프 유지 [확정] |
| 8 | 하단 탭 | 홈 / 기록 / 농장 / 마이 |

**상태별**
- 운동 이력 없음(신규): 요약·캘린더·최근 운동 영역은 "첫 1분을 시작해 보세요" 안내 한 줄로 대체, 주간 그래프 숨김
- 불러오기 실패: 카드별 [다시 시도]

### M-03 운동 영상
**목적**: 첫 재생부터 구령과 시범을 보며 따라 한다.

| # | 요소 | 동작 |
|---|---|---|
| 1 | 상단 바 | 동작 이름, 진행(예: 2/3), 세션 남은 시간 |
| 2 | 영상 영역 | 자동 재생. 세로(9:16)·가로(16:9) 영상 모두 지원 [확정]. 영상 끝나면 다음 슬롯 자동 재생 |
| 3 | 차 안 가능 배지 | 해당 동작이 차 안 가능일 때 "주차 중일 때만 해주세요" 표시 |
| 4 | 안전 안내 | "통증이나 어지러움이 느껴지면 즉시 멈춰주세요" 상시 표시 |
| 5 | **[이전 동작]** | 직전 슬롯으로 돌아가 처음부터 재생. 첫 슬롯이면 비활성 |
| 6 | **[다음 동작]** | 현재 영상을 넘기고 **다른 영상으로 교체**해 총 설정 시간 유지 [확정]. 넘긴 시점까지 재생한 시간은 운동 시간에 포함 [확정] |
| 7 | **[그만하기]** | 확인 없이 M-04로 이동 |
| 8 | 일시정지/재생 | 영상 영역 탭. 일시정지 중에는 시간이 쌓이지 않음 |

**시간 측정**: 영상이 실제 재생 중일 때만 초 단위로 누적. 동작별 재생 초와 건너뜀 여부를 함께 저장.
**마지막 영상 종료**: 자동으로 M-04로 이동.
**화면 꺼짐 방지**: 지원 기기에서 켬. 미지원 시 무시 [확정: "가능한 기술 검토"].
**예외**
- 영상 로드 실패: "영상을 불러오지 못했어요" + [다시 시도] [그만하기]
- 앱이 백그라운드로 가거나 탭이 숨겨지면 재생 일시정지, 돌아오면 [이어하기] 표시
- 새로고침/강제 종료 시 그때까지의 재생 시간을 저장하고, 다음 실행 때 [이어서 하기]로 재개할 수 있다 [확정 ⑰]

### M-04 운동 완료
**목적**: 칭찬하고 보상을 주며 다음 행동을 안내한다.

**A. 인정 시간 1분 이상**
| # | 요소 | 동작 |
|---|---|---|
| 1 | 칭찬 문구 | 예: "오늘도 움직였어요!" |
| 2 | 운동 시간 | 인정 시간(1·3·5분) 표시 |
| 3 | 체감 난이도 | 3단계 선택 버튼, **생략 가능** [확정]. 선택 항목: **가벼웠어요 / 적당했어요 / 힘들었어요** [확정 ⑱] |
| 4 | 물방울 획득 | +n개 애니메이션. 하루 5개 한도에 도달하면 "오늘 물방울은 다 모았어요" |
| 5 | **[농장 가기]** | F-01로 이동 |
| 6 | **[홈으로]** | H-01로 이동 |

**B. 인정 시간 0 (1분 미만)** [확정]
- 격려 문구만 표시, 기록·보상 없음
- 버튼: **[다시 해보기]**(M-01) / **[홈으로]**

**C. 로그인 권유 (C-01)**: 사용자의 **첫 번째 완료(A 화면)** 직후 1회 바텀시트
| 요소 | 동작 |
|---|---|
| 문구 | 기록과 작물을 저장해 두자는 안내 |
| [카카오로 계속] | 카카오 로그인 → 비회원 기록 이전 |

## 10. 개발 방식: 로컬 우선, 베타에서 서버 연결

### 10-1. 원칙
- 1차(로컬): 서버·외부 계정 없이 한 대의 PC/폰 브라우저에서 모든 핵심 흐름을 동작시킨다.
- 2차(베타): 같은 화면을 유지한 채 저장소와 로그인만 서버(Supabase 등)로 교체한다.
- 이를 위해 데이터 접근을 한 곳(데이터 접근 계층)으로 모은다. 화면은 이 계층만 호출하고, 로컬 구현을 서버 구현으로 바꾸면 화면 수정은 없다.

### 10-2. 로컬 단계에서 되는 것 / 안 되는 것
| 기능 | 로컬 단계 | 방법 | 베타에서 바꾸는 것 |
|---|---|---|---|
| 자세·시간·영상·완료 흐름 | ✅ 전부 | 영상 파일은 프로젝트 안 폴더에 둠 | 영상을 저장소/CDN으로 이전 |
| 운동 시간 측정·인정 시간·물방울 | ✅ | 기기 저장소 | 서버 저장 |
| 추천 로직 | ✅ | 앱 안에서 계산 | 그대로 또는 서버로 이동 |
| 기록·캘린더·주간 그래프 | ✅ | 기기 저장소 | 서버 저장 |
| 농장·수확·팁 카드 | ✅ | 기기 저장소 | 서버 저장 |
| 재시작 환영·문구 중복 방지 | ✅ | 기기 저장소 | 서버 저장 |
| 운동 목록·문구 관리 | ⚠ 파일(JSON)로 대체 | 프로젝트 안 JSON 파일을 수정 | 스프레드시트 **자동 반영**으로 교체 |
| 관리자 지표 | ⚠ 개발용 화면 | 기기 안 데이터로 계산하는 확인용 화면 | 서버 데이터 기반 대시보드 |
| 카카오·구글 로그인 | ❌ 모의 로그인 | 버튼만 있고 가짜 로그인 처리 | 실제 로그인 연결 + 기록 이전 |
| 푸시 알림 | ❌ 일부만 | 앱이 열려 있을 때의 인앱 알림까지만 | 서버 발송 + 웹 푸시 |
| 여러 기기·여러 사용자 | ❌ | 기기 하나에 한 사용자 | 서버 계정 |

### 10-3. 계정이 필요한 시점
| 서비스 | 필요 시점 | 비고 |
|---|---|---|
| Supabase 등 서버 | 베타 | 개발자 견적 결과에 따라 변경 가능 |
| Google Cloud 로그인 설정 | 베타 | 무료 |
| Kakao Developers 앱 등록 | 베타 | 무료, 서비스 도메인 필요 |
| Google 스프레드시트 연동 | 베타 | 서비스 계정 필요 |
| 웹 푸시 | 베타 | HTTPS 도메인 필요 |

로컬 단계에서는 위 계정이 **하나도 필요 없습니다.**

### 10-4. 로컬 단계 작업 순서
1. 정비: 의존성·Replit 설정 정리, 로컬 실행 확인
2. 데이터 접근 계층(repository) + 로컬 구현
3. 운동 목록·문구 JSON 작성 (임시 영상 포함)
4. 운동 플로우 M-01~M-04 (영상 측정 포함)
5. 홈·기록·환영
6. 농장
7. 개발용 지표 화면, 모의 로그인
8. (베타 단계) 서버·로그인·알림·스프레드시트 연결

## 12. 구현 현황과 구현 중 정한 기준 (로컬 단계)

로컬 단계(§10-4의 1~7)는 구현되어 있습니다. 구현하면서 기획서에 없어 임시로 정한 기준은 아래와 같습니다. 바꾸고 싶으면 알려 주세요.

| 항목 | 현재 기준 | 위치 |
|---|---|---|
| 동작 1개를 '완료'로 치는 기준 | 건너뛰지 않았고 영상(60초)의 80%(48초) 이상 재생 | `data/content/config.json` `completeRatio` |
| 익힌 동작의 슬롯별 노출 확률 | 10% | `config.json` `masteredChance` |
| 영상 도중 앱을 닫았을 때 | 5초마다 저장. 이어서 하지 않고 날이 바뀌거나 새 운동을 시작하면 그때까지의 시간으로 기록을 확정 | `store/AppStore.tsx` |
| 1분 미만으로 끝난 운동 | 화면·통계에는 나오지 않지만 지표용으로 기록은 남김 | `lib/stats.ts` |
| 새 동작이 섞이는 위치 | 3·5분에서 홀수 번째 칸부터 채움 | `lib/recommend.ts` |
| 주의 시작 요일 | 월요일 | `lib/date.ts` |
| 알림 | 앱이 열려 있는 동안만 (앱을 닫았을 때의 푸시는 베타) | `components/ReminderHost.tsx` |
| 환영 화면의 [이어서 하기] | 멈춘 영상이 있을 때만 표시 | `app/welcome.tsx` |
