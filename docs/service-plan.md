## 1. 서비스 목적과 검증 목표

### 1-1. 서비스 정의
- JUST MOVE는 운동을 꾸준히 하지 못하는 사람에게 **"지금 1분만 움직이기"** 를 제안하는 웹앱이다. 〔R01-01〕
- 하루를 쉬었다고 실패한 것으로 취급하지 않는다. 〔R01-02〕
- 다시 돌아온 행동을 환영한다. 〔R01-03〕

### 1-2. v1.0 검증 질문과 지표
**검증 질문**: 첫 사용 후 7일 안에 사용자가 운동을 이어가거나, 하루 이상 쉬었다가 다시 돌아와 1분 이상 움직이는가? 〔R01-04〕

| 구분 | 기획서 기준 | 계산 방법 |
|---|---|---|
| 성공 사용자 〔R01-05〕 | 첫 사용일부터 7일 안에 매일 1분 이상 운동 **또는** 1일 이상 쉬었다가 재운동 | 첫 사용일 D0~D6 중 7일 모두 움직인 날이거나, 움직인 날 사이에 1일 이상 빈 날이 있고 그 뒤 다시 움직인 날이 있으면 성공 |
| 추가 지표 〔R01-06〕 | 쉬었다 돌아온 사용자를 휴식 기간 1일 / 2일 / 3일 이상별로 분류 | 두 움직인 날 사이의 빈 날 수 = 휴식 기간 |
| 행동 기준 〔R01-07〕 | 운동 1분 이상 완료한 날을 '움직인 날'로 인정 | 하루(한국시간)에 인정 시간 1분 이상인 운동이 1회 이상 있는 날 |

**측정 요청** 〔R01-09, R01-10〕: 7일 내 운동 참여와 휴식 후 복귀를 **구분하여** 집계하고, 휴식 기간(1일/2일/3일 이상)별 복귀 현황을 **관리자에게 제공**한다. → §9

### 1-3. 운영 원칙 〔R01-08〕
**쉰 날 · 연속 기록 초기화 · 실패 표시를 사용자 화면에 드러내지 않는다.**
화면별 점검 목록은 명세 §2-2. 수정 전 코드에서 이 원칙에 걸리는 요소: 기록 탭 '최고 연속', MY '7일 연속' 배지, 기록 목록의 '부분' 표시.

### 3-1. 기존 기능 유지 또는 후순위
| 기획서 내용 | 처리 |
|---|---|
| 주간 운동시간 그래프는 기존 앱의 현 상태를 가능하면 유지 〔R03-21〕 | 수정 전 기록 탭 '주간 통계'의 일별 막대(월~일)를 **모양 그대로 유지**. 막대 값은 수정 전에는 '완료 횟수'였으므로, 기획서 표현(운동시간)에 맞춰 '운동 분'으로 바꿀지 확인 〔Q-03〕 |
| 작물 바구니는 기존 앱의 현 상태를 가능하면 유지 〔R03-22〕 | 수정 전 코드에는 바구니가 없음. 기준이 되는 다른 버전이 있는지 확인 〔Q-07〕. 없으면 명세 F-01대로 신규 구현 |
| 개인 목표 변경 기능은 확장하지 않는다 〔R03-23〕 | 목표는 "하루 1분" 고정 표시, 변경 화면 없음 |
| 운동 부위 선택 화면은 제거 〔R03-24〕 | 수정 전 코드에는 없음(README 개발 예정 항목). 만들지 않음 |
| 부위는 추천 로직 내부에서만 사용 〔R03-25〕 | §7-2 규칙 4(같은 부위 연속 방지)에만 사용, 화면에서 고르지 않음 |

### 3-2. 기획서에 언급이 없는 기존 기능
수정 전 앱에 있었지만 기획서가 언급하지 않은 기능은 **모두 유지**한다 〔D-16〕. 화면 디자인도 수정 전과 비슷하게 유지한다 → [design-spec.md](design-spec.md)

| 유지하는 기존 기능 | 조정 |
|---|---|
| MOVE 포인트·레벨(5단계)·배지 | '7일 연속' 배지만 운영 원칙 〔R01-08〕 때문에 제외. 포인트는 운동 1회 안에서 완료한 동작마다 난이도 포인트 |
| 인증사진 | 운동 1회에 연결 |
| 운동 예약·예약 시각 알림 | 진입점을 홈·MY로 옮김(운동 상세 화면이 없어져서) |
| 홈의 오늘 통계 카드·보상 요약 카드·오늘 예약 | 첫 화면 아래로 이동 〔D-18〕 |
| 홈의 빠른 자세 선택 | [지금 움직이기]와 중복이라 안내 문구로 바꿈 〔D-18〕 |
| 완료 화면 2단계(입력 → 보상), 횟수·메모 입력, [기록 보기] | 횟수는 동작별 선택 입력 |
| 영상 화면의 목표·시간·부위·안내 문구 | 운동 목록에 목표량·주의사항·난이도 필드 유지 |
| 운동 탭 | 하단 탭 5개(홈/운동/기록/농장/MY) 〔D-17〕 |
| 기록 탭 3구간(최근 기록/주간/월간), 월간 응원 문구, 캘린더 횟수 | 그대로 (연속 기록·'부분' 표시만 제외) |
| 기록 삭제 | 보류 결정 유지 〔D-12〕 |

**오늘의 한마디** 〔R04-01〕: 홈 상단 문구. 시간대(아침/오후/저녁)별로 스프레드시트에서 관리 (시간대 구분은 해석).

## 6. 운동 기록·보상·알림·계정 규칙

### 6-1. 운동 시간과 기록 〔R03-06, R04-31, D-02〕
| 용어 | 정의 |
|---|---|
| 운동 1회(세션) | 시간 선택(M-02) 직후부터 완료(M-04) 도착까지 |
| 실제 운동 시간 | 영상이 재생 중이었던 시간의 합(초). 넘긴 영상도 넘기기 전까지 본 시간은 포함 |
| 인정 시간 | 실제 운동 시간을 1·3·5분 단위로 내린 값: 1분 미만 0 / 1분 이상 1 / 3분 이상 3 / 5분 이상 5 (예: 4분 30초 → 3분) |
| 기록 | 인정 시간 1분 이상이면 기록·물방울. 1분 미만이면 보상 없이 격려 |
| 움직인 날 | 인정 시간 1분 이상 운동이 1회 이상 있는 날 (한국시간 기준) |
| 앱 종료 시 | 영상 도중 앱이 꺼져도 그때까지의 시간을 저장, 다음 실행 시 [이어서 하기] 〔D-10〕 |

### 6-2. 체감 난이도 〔R03-08, R04-17, D-11〕
- 완료 화면에서 **가벼웠어요 / 적당했어요 / 힘들었어요** 중 선택, 생략 가능
- 수정 전 앱은 운동 고유 난이도로 '가볍게/보통/도전'을 자동 기록했음 → 사용자가 고르는 방식으로 변경

### 6-3. 물방울·농장 〔R03-14~16, R06-11~19〕
| 항목 | 기획서 원문 | 확정 |
|---|---|---|
| 물방울 지급 | 1분 이상 운동 1회당 1개 | **인정 시간 1분당 1개** (1분 → 1개, 3분 → 3개, 5분 → 5개) 〔D-01〕 |
| 하루 한도 | 하루 최대 5개 | 동일. 한도 이후에도 운동·기록은 계속 가능 |
| 작물 성장 | 물방울 7개를 사용하면 방울토마토 1개 수확 | 동일. 물주기는 사용자가 [물주기]를 눌러 1개씩 사용 (F-01 '물주기' 요소) |
| 성장 제한 | 하루 성장 제한 없음 | 동일 |
| 수확 시 | 바구니 토마토 +1, 레시피/건강 팁 카드 1개 오픈, 새 작물 시작 | 동일 |
| 보존 원칙 | 쉬었다고 작물이 시들거나 수확물이 감소하지 않음 | 동일 |
| 추후 확장 | 쿠폰, 지역 농산물 지급은 v1.0 이후 검토 | v1.0 범위 외 (§12) |

### 6-4. 알림 〔R03-17, R03-18, R06-20~31〕
| 항목 | 기획서 내용 | 확정·구현 방식 |
|---|---|---|
| 기본값 | 오전 9시 ~ 오후 8시 매시 정각 | 원안 유지 〔D-07〕 |
| 사용자 변경 | 시작 시간, 종료 시간, 간격, 켜기/끄기 | 시작·종료·켜기/끄기 변경 가능. **간격은 1시간 고정** 〔D-07〕 — 기획서와 다른 점이라 재확인 권장 〔Q-12〕 |
| 미루기 | 알림에서 "1시간 뒤 / 3시간 뒤 / 오늘은 그만" | 아이폰 웹 푸시는 알림 안 버튼이 제한될 수 있어, 알림을 누르면 열리는 앱 안 선택 화면으로 제공 (Android는 버튼 병행 검토) |
| 중지 조건 | 하루 물방울 5개 획득 후 중지 | 동일 |
| 문구 | 운동하지 않은 사람 / 이미 움직인 사람 구분, 스프레드시트 관리 | 동일 |
| 검증 | 아이폰 웹 푸시, 알림 내 액션 버튼 지원 범위는 개발자가 검증 | §11 답변 |
| 협의 | 기본 시간당 1회, 피로도·웹 푸시 제약을 고려해 착수 전 재검토 | 기획자 검토 결과 **원안 유지** 〔D-07〕 |

### 6-5. 계정·기록 이전 〔R03-19, R03-20, R04-36~38〕
- 로그인 수단: 카카오, 구글
- 권유 시점: 첫 운동 완료 직후 1회, "나중에 하기" 제공. 이후에는 마이에서 로그인
- 기록 이전: 처음 실행할 때부터 기기에 익명 사용자로 저장하고, 로그인하면 그 기록과 농장을 계정에 이어 붙인다
- 이미 다른 기기에서 쓰던 계정이면: 운동 기록·수확 수·보유 물방울은 합치고, 작물 진행도는 큰 값을 쓴다 (해석, 확인 권장 〔Q-13〕)

### 6-6. 데이터 보관·탈퇴 〔R07-24, D-06〕
- 계정 정보(로그인 식별자, 알림 구독 정보)는 **즉시 삭제**
- 운동 기록은 누구의 것인지 알 수 없게 바꿔 **통계에만 사용**

## 7. 운동·추천·안전 규칙

### 7-1. 동영상 기본 요건 〔R05-01~07, R05-22, R05-23〕
| 항목 | 기획서 내용 |
|---|---|
| 길이 | 각 영상 1분 |
| 녹음 | 구령과 간단한 동작 설명을 함께 녹음 |
| 따라 하기 | 사용자는 처음부터 시범을 보며 따라 한다. 첫 재생부터 함께 따라 하고, **별도의 사전 시청 단계는 두지 않는다** |
| 3·5분 | 1분짜리 영상을 연속 재생 |
| 하지 않는 것 | 별도의 "소리만 듣기" 기능은 만들지 않는다 |
| 화면 꺼짐 | 영상 중 화면이 꺼지지 않도록 가능한 기술을 검토 → 화면 꺼짐 방지 기능 사용(지원 브라우저) |
| 안전 안내 | 화면에 **"통증이나 어지러움이 느껴지면 즉시 멈춰주세요"** 표시 |
| 영상 방향 | 세로(9:16)·가로(16:9) 모두 지원 〔D-08〕. 현재 보유 영상은 세로 |

### 7-2. 추천 우선순위 (기획서 원본 기준)
| 순서 | 규칙 |
|---|---|
| 1 〔R05-08〕 | 선택한 자세에 맞는 운동만 후보로 삼음 |
| 2 〔R05-09〕 | 1~4회 완료한 "익히는 중"인 동작을 우선 추천 |
| 3 〔R05-10〕 | 3·5분에서는 익히는 중인 동작과 새로운 동작을 혼합 (새 운동 비율 30% 〔D-14〕) |
| 4 〔R05-11〕 | 바로 전 동작과 같은 부위가 연속되지 않도록 구성 |
| 5 〔R05-12〕 | 5회 완료하면 "익힌 동작"으로 분류해 가끔 노출 |
| 6 〔R05-13〕 | 건너뛴 동작도 당일 재추천 가능 |

- 처음 사용하는 사람(완료 0회)의 첫 동작은 '첫 동작 여부'가 지정된 동작 〔R05-14〕
- '다음 동작'으로 넘긴 자리에도 같은 규칙으로 다른 동작을 고른다 〔R04-34〕
- 기획서에 없어 임시로 정한 값(확인 필요 〔Q-14〕): 동작 1개 '완료' 기준 = 영상의 80% 이상 재생, 익힌 동작 노출 확률 = 동작 칸마다 10%

### 7-3. 관리 데이터 〔R05-14~19, R05-21〕
**운동 목록 필드** (기획서): 동작 이름 / 자세 / 부위 / 차 안 가능 여부 / 영상 URL / 첫 동작 여부
추가 필드(구현에 필요): 영상 방향, 사용 여부, 한 줄 설명

**운영자가 변경할 설정** (기획서): 익힌 동작 기준 횟수(5), 새 운동 비율(30%), 하루 물방울 한도(5), 수확에 필요한 물방울 수(7), 알림 기본값(9~20시, 켜짐)

**스프레드시트로 관리할 것** 〔R06-09, R06-28, R07-17〕: 운동 목록, 환영 문구, 알림 문구, 레시피·건강 카드(+ 오늘의 한마디, 설정값). 시트 내용은 **자동 반영** 〔D-13〕

**차 안 가능 여부** 〔R05-20, R05-21〕: 추천 목록이 이 값을 가지고 있어야 차 안 동작을 적절히 노출할 수 있다. 차 안 가능 동작에는 **"주차 중일 때만 해주세요"** 안내를 붙인다.

### 7-4. 콘텐츠 준비 (기획자) 〔R07-03~07〕
| 항목 | 기획서 | 현재 상태 |
|---|---|---|
| 영상 | 약 20개 (자세별 약 5개) | 목록·파일 이름 정리됨(`public/videos/README.md`), 파일 대기 |
| 첫 동작 지정 | 자세별 첫 동작 | 초안 지정, 기획자 확인 필요 |

### JUST MOVE 웹앱 개발 기획서

v1.0 | 개발 협의 및 견적 요청용 | 2026년 10월 18일

#### 01. 서비스 목적과 검증 목표

JUST MOVE는 운동을 꾸준히 하지 못하는 사람에게 “지금 1분만 움직이기”를 제안하는 웹앱이다. 하루를 쉬었다고 실패한 것으로 취급하지 않고, 다시 돌아온 행동을 환영한다.

##### v1.0의 검증 질문

첫 사용 후 7일 안에 사용자가 운동을 이어가거나, 하루 이상 쉬었다가 다시 돌아와 1분 이상 움직이는가?

| 구분 | 원본 기획 기준 |
| --- | --- |
| 성공 사용자 | 첫 사용일부터 7일 안에 매일 1분 이상 운동 또는 1일 이상 쉬었다가 재운동 |
| 추가로 볼 지표 | 쉬었다 돌아온 사용자를 휴식 기간(1일/2일/3일 이상)별로 분류 |
| 행동 기준 | 운동 1분 이상 완료한 날을 ‘움직인 날’로 인정 |
| 운영 원칙 | 쉰 날·연속 기록 초기화·실패 표시를 사용자 화면에 드러내지 않음 |

측정 요청: 7일 내 운동 참여와 휴식 후 복귀를 구분하여 집계하고, 휴식 기간(1일/2일/3일 이상)별 복귀 현황을 관리자에게 제공한다.

#### 02. 대표 사용자

48세 여성 보험사 상담원. 출퇴근과 외근이 불규칙하고, 정장 차림·짧은 대기 시간·차량 주차 중에도 운동할 수 있어야 한다. 발바닥 통증으로 서서 하는 운동에 부담이 있으며, 체중 감량보다 몸이 가벼워지는 경험을 원한다.

핵심 사용 맥락: 앉아서 / 누워서 / 서서 / 걸으면서 할 수 있는 1분 동작. 사용자가 고민하거나 여러 화면을 탐색하기 전에 바로 시작하도록 설계한다.

※ 자동차 관련 운동은 운전 중 금지. 반드시 안전하게 주차된 상태에서만 이용하도록 안내.

#### 03. v1.0 기능 범위와 우선순위

기존 웹앱을 재사용·보완할 수 있는지 우선 검토한다. 아래 항목은 v1.0 목표 기능이며, 실제 착수 범위는 견적 협의 후 확정한다.

| 우선순위 | 기능 | 구현 핵심 |
| --- | --- | --- |
| 필수 | 운동 시작 | 자세(누워/앉아/서/걸으며)와 시간(1·3·5분) 선택 → 추천 즉시 시작 |
| 필수 | 운동 영상 | 구령과 시범이 포함된 1분 영상. 3·5분은 1분 영상 이어 재생 |
| 필수 | 운동 기록 | 1분 이상 수행 시 기록·완료 피드백·체감 난이도 선택(선택 입력) |
| 필수 | 다시 시작 환영 | 하루 이상 쉬고 재방문하면 기존 작물과 함께 환영 문구 노출 |

##### 기존 기능 유지 또는 후순위

주간 운동시간 그래프와 작물 바구니는 기존 앱의 현 상태를 가능하면 유지한다. 개인 목표 변경 기능은 확장하지 않는다. 운동 부위 선택 화면은 제거하고, 부위는 추천 로직 내부에서만 사용한다.

##### 개발 범위를 나눠 견적 받기

A안: 운동·영상·기록·재방문 환영 중심의 최소 구현. B안: 원본의 필수 범위 전체(농장·알림·로그인 포함). 두 범위 각각 개발 기간·비용·유지비를 산정 요청.

견적 요청: A안과 B안을 구분하여 개발 기간, 초기 비용 및 월 운영비를 각각 제시해 주세요.

##### 주요 흐름

앱 실행 → (하루 이상 쉬었다면 환영 화면) → 홈 → 자세 선택 → 시간 선택 → 운동 영상 → 완료·난이도 → 물방울 → 농장 또는 홈

##### 분기 처리

- 영상 중간 종료: 실제 운동한 시간이 1분 이상이면 해당 시간만 기록·물방울 제공. 1분 미만이면 보상 없이 격려한다.

- 다음 동작 넘기기: 3·5분의 총 설정 시간은 유지하며, 넘긴 자리에 다른 영상을 추천한다. 이전 동작으로 되돌릴 수 있다.

- 로그인: 첫 운동 완료 후 권유하고 “나중에 하기” 제공. 로그인 전 기록은 이후 계정에 이어 붙인다.

협의 필요: 영상을 넘길 때의 시청 시간·실제 운동 시간·물방울 지급 기준을 개발 전 확정한다.

#### 05. 운동·추천·안전 규칙

##### 동영상 기본 요건

각 영상은 1분 분량이며 구령과 간단한 동작 설명을 함께 녹음한다. 사용자는 처음부터 시범을 보며 따라 한다. 3분·5분은 1분짜리 영상을 연속 재생하고 별도의 “소리만 듣기” 기능은 만들지 않는다.

영상 중 화면이 꺼지지 않도록 가능한 기술을 검토한다. 화면에는 “통증이나 어지러움이 느껴지면 즉시 멈춰주세요”라는 안전 안내를 보여준다.

##### 추천 우선순위(원본 기준)

| 순서 | 규칙 |
| --- | --- |
| 1 | 선택한 자세에 맞는 운동만 후보로 삼음 |
| 2 | 1~4회 완료한 “익히는 중”인 동작을 우선 추천 |
| 3 | 3·5분에서는 익히는 중인 동작과 새로운 동작을 혼합 |
| 4 | 바로 전 동작과 같은 부위가 연속되지 않도록 구성 |
| 5 | 5회 완료하면 “익힌 동작”으로 분류해 가끔 노출 |
| 6 | 건너뛴 동작도 당일 재추천 가능 |

##### 관리 데이터

운동 목록 필드: 동작 이름 / 자세 / 부위 / 차 안 가능 여부 / 영상 URL / 첫 동작 여부. 운영자가 변경할 설정: 익힌 동작 기준 횟수, 새 운동 비율, 하루 물방울 한도, 수확에 필요한 물방울 수, 알림 기본값.

##### 안전·운영 확인

차 안 동작은 “주차 중일 때만 해주세요”라는 안내를 추가한다. 특히 추천 목록에서 차 안 가능 여부를 갖고 있어야 적절하게 노출 가능하다.

영상 기준: 첫 재생부터 구령과 시범을 보며 함께 따라 한다. 별도의 사전 시청 단계는 두지 않는다.

#### 06. 재방문·농장·알림 운영 규칙

##### 재방문 환영

하루 이상 운동을 쉬고 다시 앱을 연 사용자는 홈보다 먼저 환영 화면을 본다. 쉰 날 수와 재시작 횟수는 표시하지 않으며, 작물은 쉬기 전 상태 그대로 보여준다. “바로 1분 하기”와 “홈으로 가기” 버튼을 제공한다.

환영 문구는 휴식 기간(1~2일/3일 이상), 이용 관계(앱 이용 1개월 초과·운동 20일 이상 여부)별로 다르게 제시한다. 문구는 운영자 스프레드시트로 관리하고 최근 2개 중복 노출은 방지한다.

##### 농장 보상

| 항목 | 규칙 |
| --- | --- |
| 물방울 지급 | 1분 이상 운동 1회당 1개, 하루 최대 5개 |
| 작물 성장 | 물방울 7개를 사용하면 방울토마토 1개 수확; 하루 성장 제한 없음 |
| 수확 시 | 바구니 토마토 +1, 레시피/건강 팁 카드 1개 오픈, 새 작물 시작 |
| 보존 원칙 | 쉬었다고 작물이 시들거나 수확물이 감소하지 않음 |
| 추후 확장 | 쿠폰, 지역 농산물 지급은 v1.0 이후 검토 |

##### 알림(원본 확정안 · 기술 및 이용성 검토 필요)

기본값은 오전 9시~오후 8시 매시 정각. 사용자가 시작·종료 시간, 간격, 켜기/끄기를 변경할 수 있다. 알림에서 “1시간 뒤 / 3시간 뒤 / 오늘은 그만” 선택 가능하도록 제안하며, 하루 물방울 5개 획득 후에는 중지한다.

운동하지 않은 사람과 이미 움직인 사람에게 알림 문구를 달리 제시한다. 문구는 스프레드시트에서 관리한다. 아이폰 웹 푸시 및 알림 내 액션 버튼 지원 범위는 개발자가 검증한다.

협의 필요: 현 기획상 기본 알림은 시간당 1회이나, 사용자 피로도와 웹 푸시 제약을 고려하여 기본 빈도 및 구현 방식을 착수 전 재검토한다.
